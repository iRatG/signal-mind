## Контекст: откуда мы пришли

### Phase A — Старый агент (src/agent/)
**Что было хорошо:**
- RAG → LLM генерация гипотез из корпоративных отчётов
- Компании сами говорят о своих рисках и чувствительностях к рынку
- Ouroboros feedback loop: следующая гипотеза учитывает результат предыдущей
- ChromaDB: 15 574 чанков (Sberbank, Lukoil, Gazprom, Yandex, Nornikel)
- 1 918 чанков ЦБ РФ (регуляторные документы)
- DeepSeek LLM для рассуждений и генерации

**Что было плохо:**
- Нет правильных сплитов данных (смотрели на всё подряд → data snooping)
- Нет z-score нормализации → режимные артефакты
- Нет формальной статистической проверки (только SQL + LLM-оценка)
- Нет integrity checking → самообман возможен

### Phase B — Pipeline v2 (src/pipeline_v2/)
**Что было хорошо:**
- z-score нормализация window=90 — критически важно
- M5 (Mann-Whitney U) + M6 (LightGBM IC) — двойная независимая проверка
- Train 2022-2023 / Val 2024-2025 / Test 2025-2026 — правильные сплиты
- Scientific ledger: integrity flags, enrichment vs random, anti-patterns
- Session knowledge: система учится между запусками (session_config.json)
- Task Scheduler: автономная работа 06:00/14:00/22:00

**Что было плохо:**
- Нет интеллекта в выборе гипотез — тупой перебор 672 комбинаций
- RAG не используется — корпоративные отчёты лежат мёртвым грузом
- Нет экономического обоснования найденных сигналов
- Зашоренность: ищем только то что уже умеем искать

## Phase C — Принцип

> **RAG даёт интеллект. Pipeline_v2 даёт строгость. Phase C объединяет оба.**

Корпоративные отчёты и регуляторные документы содержат:
- Конкретные чувствительности: "ставка +1% → прибыль -3%"
- Временные горизонты: "эффект реализуется в течение квартала"
- Причинно-следственные связи: "санкции → ограничение экспорта → выручка"
- Прогнозы менеджмента: были ли они правы?

Это **готовые гипотезы** с экономическим обоснованием.  
Phase B умеет их **строго проверять** на данных.  
Phase C это соединяет.

```
  "ЦБ: при ставке выше 18% банковский сектор испытывает давление"
  "ЦБ: инфляционные ожидания влияют на USD/RUB с лагом 2-4 нед"
  → Макро-обоснование гипотез

Слой 3: Obsidian Vault (ChromaDB: methodology)
  "Этот сигнал уже проверяли — не подтвердился в 2023"
  "Подход устарел (режим изменился)"
  "Этот инструмент ещё не тестировали"

```

- Известные сигналы и их статус
- Открытые атаки и слабости
- Устаревшие подходы
- Карта непроверенных инструментов

Используется через `src/agent/rag.py`:  
`search_methodology()` и `get_methodology_context()`

## Ключевые принципы Phase C

1. **Гипотезы из документов, не из перебора**  
   Каждая гипотеза имеет источник (компания, год, страница).  
   Система объясняет механизм, не просто называет корреляцию.

2. **Строгая валидация (Phase B методология)**  
   z-score window=90, M5+M6, правильные сплиты.  
   Integrity check на каждой сессии.

3. **Новые сигналы**  
   Не используем найденные сигналы Phase A/B как семена.  
   Пусть система сама найдёт — без предвзятости.

4. **Честность**  
   Каждый результат: IC, p-value, enrichment vs random, цитата из источника.  
   Если нет обоснования в документе — сигнал помечается как "empirical only".

5. **Ретроспективная проверка**  
   Газпром говорил X в 2022 → проверяем: сбылось ли к 2023-2024?  
   Это даёт оценку достоверности самих отчётов.

## Порядок реализации

### Шаг 1: hypothesis_schema.py
Датакласс `RagHypothesis` — структура одной гипотезы из отчёта.

### Шаг 2: rag_extractor.py  
Для каждой компании × года:
- Запрос к ChromaDB: "чувствительность к рынку", "факторы риска", "прогнозы"
- LLM (DeepSeek) читает чанки → структурированный JSON гипотез
- Сохраняет в `analytics/phase_c/hypotheses/`

### Шаг 3: hypothesis_tester.py
- Принимает `RagHypothesis`
- Определяет feature (keyword_z90 или embedding_z90)
- Тестирует все лаги из `lag_range`
- Возвращает результаты M5+M6

### Шаг 4: phase_c_runner.py
- Оркестратор: extractor → tester → ledger → report
- Ouroboros: обновляет знания о компаниях
- Может работать в том же Task Scheduler

### Шаг 5: интеграция в расписание
- Утром (06:00): Phase C runner
- Анализ (13:00): оба анализатора (B + C)
- Днём (14:00): Phase B + Phase C параллельно (или чередуем)
