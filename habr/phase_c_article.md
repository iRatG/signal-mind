# 615 сессий, 1428 комбинаций, 0 сигналов — и почему это правильный ответ

*Продолжение серии «Signal Mind». Часть 3.*

---

Во второй статье мы получили два настоящих сигнала из нескольких тысяч гипотез. Поставили правила: LLM генерирует, статистика решает. Добавили z-score нормализацию, три непересекающихся окна, BH-коррекцию на множественное тестирование.

Это была хорошая методология. Оставался один вопрос.

**Мы покрыли всё пространство?**

В Phase B мы искали там где было интересно. LLM предлагал гипотезы — мы проверяли. Но LLM имеет привычки: он возвращается к знакомым инструментам, игнорирует «скучные» темы, не замечает неочевидных лагов. Мы не знали сколько комбинаций осталось непроверенными.

Phase C отвечала ровно на этот вопрос.

---

## Задача: исчерпать пространство полностью

Мы зафиксировали пространство поиска:

- **17 инструментов:** USD/RUB, EUR/RUB, Brent, Gold, Silver, S&P500, MSCI World, DXY, MSCI India, China H-Shares, FTSE China 50, DJ South Africa, IMOEX, MOEXFN, MOEXOG, MOEX10, RUGOLD
- **7 тем:** oil, rate, ruble, sanctions, inflation, banking, gold
- **12 лагов:** 1, 2, 3, 5, 7, 10, 14, 21, 30, 45, 60, 90 дней
- **Итого:** 17 × 7 × 12 = **1 428 комбинаций**

Цель: протестировать каждую. Без исключений.

---

## Как мы это автоматизировали

Вручную 1 428 комбинаций — это недели. Мы запустили автономный цикл через Windows Task Scheduler:

```
22:00  → 05:30  Ночная сессия   (7.5 часов)
07:00  → 14:00  Утренняя сессия (7 часов)
15:00  → 21:00  Дневная сессия  (6 часов)
```

20+ часов поиска каждые сутки. Единственная защита от конфликтов — lock file:

```python
LOCK_FILE = Path("db/phase_c.lock")

def acquire_lock():
    if LOCK_FILE.exists():
        sys.exit(0)          # другой экземпляр уже работает
    LOCK_FILE.write_text(str(os.getpid()))

def release_lock():
    LOCK_FILE.unlink(missing_ok=True)
```

Если один экземпляр завис — следующий запуск просто не стартует. Без конфликтов, без дублей, без потерянных данных.

**12 дней. 615 сессий. Ноль крашей.**

## Проблема в середине пути

Примерно на 300-й сессии pipeline встал.

Симптом: Ouroboros предлагал гипотезы — но всё что он предлагал уже было проверено. Агент ходил по кругу.

Диагноз: к тому моменту было протестировано 653 комбинации. Но в промпт мы передавали только **30 последних** — чтобы не раздувать контекст. LLM видел 30 из 653 и генерировал из той же области. Остальные 623 комбинации для него не существовали.

Это типичная ловушка LLM-систем с внешней памятью: когда память велика — её нужно показывать выборочно. Но неправильная выборка = туннельное зрение.

**Фикс:** Strategy E. Вместо случайных прошлых тестов — показываем 40 **нетестированных** комбинаций:

```python
def _get_untested_hint(self, n=40):
    all_combos = set(product(INSTRUMENTS, TOPICS, LAGS))
    tested = {(r["instrument"], r["topic"], r["lag"]) 
              for r in self.ledger}
    untested = list(all_combos - tested)
    return random.sample(untested, min(n, len(untested)))
```

Теперь агент знает куда ещё не ходил. Он может идти туда сам — или система идёт туда детерминированно, по 14 комбо за итерацию, пока пространство не исчерпано.

**Именно так мы нашли тему banking** — MSCI India/banking/lag=2 и S&P500/banking/lag=7. LLM никогда не предложил бы «banking» сам: это не очевидная гипотеза в контексте российских рынков. Нашёл exhaustive sweep.

## Почему ноль — это не провал

Первая реакция на IC_test = 0.000 по всем 13 сигналам — что-то сломалось.

Мы проверили: данные корректны, логика верна, Test период (2025-05-01 → 2026-06-01) никогда не видел агент. Всё чисто.

Просто сигналы действительно не работают на Test.

**Почему?**

Смотрим на паттерн. Все 13 сигналов — **Grade D**: Val pass (2024-2025), Train fail (2022-2023). Ни один не прошёл оба периода. Связи появились **после 2023 года** в специфических условиях — санкционное давление, высокая ставка ЦБ, экстремальная инфляция. К маю 2025 режим сменился. Связи растворились.

Это называется **режимный сдвиг**. И это не артефакт — это реальность российских рынков 2022-2026.

```
Train 2022-2023:   режим А (кризис)     → сигналов нет
Val   2024-2025:   режим Б (адаптация)  → 13 сигналов
Test  2025-2026:   режим В (новый)      → 0 из 13 выживает
```

Hit rate 0.91% (13/1428) выше теоретического FDR 0.25% — значит сигналы реальные, не шум. Но ситуативные, а не структурные.

**Это честный результат:** в пространстве 17 × 7 × 12 с текущей методологией нет ни одной устойчивой межрежимной связи. Нулевая гипотеза не отвергнута.

## Что мы узнали про LLM в поисковых системах

В Phase B мы поняли: LLM генерирует, статистика решает.

В Phase C добавили: **LLM не покрывает пространство равномерно**.

Левая часть таблицы — гипотезы которые LLM предложил сам. Правая — нашёл exhaustive sweep:

| Нашёл LLM | Нашёл sweep |
|-----------|-------------|
| DXY/oil, USD_RUB/gold | MSCI_INDIA/banking/lag=2 |
| EUR_RUB/inflation | SP500/banking/lag=7 |
| DJ_SOUTH_AFRICA/gold | — |

LLM хорошо работает в зонах где у него есть интуиция: нефть → рубль, санкции → MOEX. Он плохо работает в неочевидных углах пространства: нестандартные лаги, неожиданные инструменты.

Для полного покрытия нужны оба подхода: LLM для смысловых гипотез + детерминированный sweep для систематики.

## Что дальше

**Пространство исчерпано.** Искать в 7 × 17 × 12 больше нет смысла. Нужно либо расширять пространство, либо менять подход.

Три направления которые мы видим:

**1. Новые темы.** Текущие 7 тем — это словарь 2022-2023. Режим 2025-2026 работает через другие категории: geopolitics, credit, trade, energy transition. Phase D — с обновлённым словарём.

**2. Rolling retraining.** Все найденные сигналы — ситуативные. Правильный ответ — не искать вечный сигнал, а переобучать модель каждый квартал на последних 12-18 месяцах. Тогда Grade D превращается в рабочий инструмент: «сигнал работает сейчас».

**3. Детектор режима.** Прежде чем искать сигналы — понять в каком режиме рынок. Разные режимы требуют разных гипотез. Это не улучшение поиска — это смена архитектуры.
